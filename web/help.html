A SMALL GUIDE TO YOUR ARCHIVE

Save today. Keep access tomorrow.

Model Vault is your local library of selected open-weight models: exact versions, supporting files, and resumable downloads. Learn what it saves, where it saves it, and how each feature works.

Why keep a local archive?

A model available today may not stay accessible forever. A publisher might remove a repository, change access conditions, or stop providing a particular version. These are possible reasons to preserve a copy, rather than a prediction that every model will disappear.

A local copy preserves the version you chose for future experiments, offline use, and repeatable work. Available model cards, license files, tokenizer/config assets, and source metadata provide context for using that copy later.

Open-weight does not automatically mean unrestricted or open-source. The model’s license and access terms still apply. A single HDD copy is also not a complete backup: keep a second copy of important archives.

Download one specific model

On Dashboard, use Download a specific model. Paste a Hugging Face repository page URL or owner/repo, choose GGUF/quantization or native safetensors, then Preview files & size. Review the pinned revision, files, license and space before ticking the checkbox and selecting Download only this model.

This uses a separate saved plan; your main queue and catalog choices stay unchanged. Follow Worker activity and use Stop safely if needed. Preview again to resume the same revision with existing checkpoints. Main queue totals do not include separate jobs. Gated repos need access and a configured token; custom .bin/adapters need manual setup.

A simple workflow

  1. Connect your driveWait for external drive to mount. Check Drive connected, free space, and the reserve. Opening the dashboard never starts a download.
  2. Explore the queueClick category or publisher counts to filter models. Badges identify categories; expand View files to inspect filenames, sizes, licenses, and pinned revisions.
  3. Review the entire queueCheck all models, total size, and available space, then tick the review checkbox. Filters only change your view: Start and Verify act on the full pinned queue.
  4. Start / ResumeThe downloader fetches files and saves partial data and durable checkpoints on the drive. Opening another dashboard view does not start a second transfer.
  5. Stop safely when neededThis signals the dashboard’s worker to stop. A network read can take until its timeout to finish. Partial files and checkpoints remain available for Start / Resume later.
  6. Verify after downloadingRecheck file checksums. Verify is disabled when no files have been downloaded. It reports missing/corrupt files; use Start / Resume to retry or repair them.

Where is everything saved?

Model data lives on your configured external drive. Dashboard code and its local index live on your Mac. Changing drive configuration changes the volume used for transfers; the paths below are generic examples.

LocationContents and purpose

filename.part + filename.checkpoint.jsonIncomplete data and its last durable offset. Keep these together; do not rename or edit them manually.

/path/to/local-models/dashboard-manager.logOutput from dashboard workers. The optional login agent uses separate logs in ~/Library/Logs/ModelVault/.

Job logs and queue health

New jobs get a unique ID, readable name, description, start/end times, elapsed duration and exit status. Worker activity lets you choose a job and filter INFO/WARN/ERROR entries. File events and durable checkpoints help track progress. Logs and metadata persist locally in job-logs/; this folder is excluded from Git.

Main queue health shows present files, partials, pending files and recorded issues. Past missing-file results can remain during a new run. Another manager is active means a separate dashboard/CLI/login worker owns the shared lock. Existing old workers keep their original logs under Legacy output; they are not interrupted for this update. Times display in your browser's local timezone. No activity does not necessarily mean failure: a network timeout may still be pending.

Your downloaded models

Downloaded models on Dashboard is your separate library. It shows completion counts, model names, sizes, revisions, verification history and saved locations. Main, single-model and previous saved queue selections are included when every selected file exists at its expected size. Partial files are excluded. Previously verified describes an earlier checksum check, not a fresh audit. Search by name or category. Untracked folders without saved plans are not indexed.

What does each feature do?

Understanding model labels

General

Broad tasks such as chat, writing, summarization, and assistance. This label does not determine refusal behavior.

Uncensored

A fine-tune labeled in the catalog for fewer restrictions. The current queue includes Dolphin3.0-Llama3.1-8B. The label does not guarantee an answer to every prompt.

Abliterated

A model modified to reduce refusal behavior. The current queue includes mlabonne_Qwen3-8B-abliterated. Evaluate output quality and behavior independently.

Reasoning / Coding / Vision

Reasoning focuses on multi-step problems, Coding on programming tasks, and Vision on understanding images. Vision may require a compatible runtime and projector file.

GGUF / Native / Quantization

GGUF is a model file format; native entries usually preserve original tensor files. Quantization such as Q4_K_M reduces storage and memory footprint. Quality, compatibility, and RAM requirements depend on the model and runtime.

Queued / Partial / Downloaded / Needs attention

Queued: no files yet. Partial: some files or durable bytes. Downloaded: all expected-size files present. Needs attention: recorded error or missing/corrupt result. An earlier Verify on an empty archive can leave missing-file results.

Power cuts, restarts, and using models

The downloader flushes/syncs data before saving a checkpoint. It resumes from the last durable offset and verifies a checksum before promoting a partial file to a final file. Drive identity checks stop transfers to an incorrect or unmounted volume. Disk, filesystem, or USB failure can still damage data; back up important copies.

Reopening the dashboard does not automatically start the queue. Use Start / Resume. The existing optional login agent can retry after explicit installation; your Mac must log in and the drive must mount.

Changing the queue

Stop the active worker and stop/remove any installed login agent. Edit catalog.json, then run .venv/bin/python vault.py plan from the project directory. Planning fetches metadata. Refresh the dashboard, review the new queue, and start it. Older model versions are not automatically deleted.

Using a downloaded model

This app archives and downloads models; it is not an inference/chat engine. Load the model in a suitable local inference runtime afterward. Fitting a model on your HDD does not mean it will fit in your Mac’s RAM. Check the model card, license, and runtime compatibility. This app does not execute downloaded repository code.

Model Vault aapke chosen open-weight models ki local library banata hai—exact versions, required files, aur download recovery ke saath. Yeh guide batati hai kya ho raha hai, kahan ho raha hai, aur har button ka kya kaam hai.

Iska purpose kya hai?

Aapka main reason sahi hai: jo model aaj available hai, zaroori nahi ki uski hosted copy hamesha accessible rahe. Publisher repository hata sakta hai, access conditions badal sakti hain, ya specific version unavailable ho sakta hai. Yeh possibilities hain—har model band hone ki prediction nahi.

Apni copy rakhne se aap selected model version ko future experimentation, offline use, aur repeatable work ke liye preserve kar sakte ho. Model card, license, tokenizer/config files aur available source metadata bhi saath aate hain, taaki baad mein pata rahe copy kis version ki hai aur use kaise karna hai.

Open-weight ka matlab automatically unrestricted ya open-source nahi. Har model ki license aur access terms apply hoti hain; local copy rakhna un terms ko override nahi karta. Archive useful hai, lekin ek hi HDD par copy hona complete backup nahi—important archives ki second copy bhi rakho.

Sirf ek specific model download karo

Dashboard par Download a specific model use karo. Hugging Face repo URL ya owner/repo paste karo, format aur quantization choose karo, phir Preview files & size. Exact revision, files, license aur space review karke checkbox tick karo aur Download only this model choose karo.

Alag saved plan use hoga; main queue aur catalog choices nahi badlenge. Worker activity dekho aur Stop safely use karo. Same revision dobara preview karke checkpoints se resume kar sakte ho. Main queue totals mein yeh separate job nahi dikhega. Gated repo ke liye access/token chahiye; custom .bin/adapters manually configure karo.

Simple workflow

  1. Drive connect karoexternal drive mount hone do. Dashboard par Drive connected, free space aur reserve check karo. Page kholne se download start nahi hota.
  2. Queue samjhoCategory / publisher counts click karke models explore karo. Har model ka badge dekho; View files se filenames, size, license aur pinned revision milti hai.
  3. Poori queue review karoTotal size, models aur available space check karo. Filters sirf view badalte hain—Start aur Verify poori pinned queue par kaam karte hain. Review checkbox tick karo.
  4. Start / ResumeDownloader files fetch karta hai. Partial data aur durable checkpoints drive par bante hain. Dashboard khula rehne se alag se koi second download nahi chalta.
  5. Zarurat par Stop safelyDashboard worker ko stop signal milta hai. Network timeout tak thoda waqt lag sakta hai. Partial files aur checkpoints retained rehte hain; baad mein Start / Resume karo.

Power cut, restart aur baad ka use

Downloader pehle data flush/sync karta hai, phir checkpoint save karta hai. Restart par last durable offset se resume hota hai; final file banne se pehle checksum verify hota hai. Drive identity guard galat/unmounted drive par transfer rokta hai. Disk, filesystem ya USB hardware failure ke against absolute guarantee nahi—important copy ka backup rakho.

Dashboard dobara open karna queue auto-start nahi karta. Manually Start / Resume karo. Existing optional login agent explicit install ke baad recovery retries provide karta hai; Mac login aur drive mount hona zaroori hai.

Queue badalni ho?

Active worker stop karo; installed login agent ko bhi stop/remove karo. Project ke catalog.json mein choices update karo, phir project directory se .venv/bin/python vault.py plan run karo. Yeh metadata fetch karta hai. Dashboard refresh karke nayi queue review karo, uske baad start karo. Purane model versions automatically delete nahi hote.

Model use kaise karunga?

Yeh app archive/downloader hai; chat ya inference engine nahi. Download ke baad suitable local inference runtime mein model load karna hoga. HDD par model fit hona aur Mac ki RAM mein run hona alag cheezein hain. Model card/license aur runtime compatibility check karo; downloaded repository code yeh app execute nahi karta.
